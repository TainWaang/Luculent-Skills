## 一、交付物与篇幅口径

用户选择PDF或PDF+Word时执行本规范。完整客户研究不得只在对话中粘贴长篇正文；PDF交付至少包含：

- 一份排版完整的客户研究PDF；
- 对话中的三至五条核心结论和PDF文件链接；
- 必要时另附证据台账，但不能要求读者依赖台账才能理解PDF。

正文控制在10,000—30,000字。只固定正文总量和分析质量，不固定纵向、横向或其他章节比例。根据用户需求、报告使用对象、客户层级、证据密度和要支持的决策动态设计目录与篇幅。

使用可提取的正文字符作为统计口径。排除封面、目录、页眉页脚、免责声明、来源清单、证据台账和附录。将表格中的短标签视为结构信息，不依靠表格单元格达到正文下限。

报告长度服从证据密度。优先深化与用户目标直接相关、能够改变销售判断的内容，不重复客户简介。公开信息确实不足时，明确说明缺口并列出所需内部材料。

## 二、报告信息架构

依据用户需求生成定制目录。面向朗坤智慧营销团队，通常保持“先看核心结论，再了解客户与相关人员，再看项目、采购和厂商，最后判断朗坤智慧可以跟进什么”的阅读路径，但不强制使用任何固定分析框架。

### 前置部分

1. 封面
2. 报告目录

封面之后只保留报告目录，随后直接进入第一章“核心结论”。不得插入使用说明、报告说明、研究方法、资料可信度规则、内部检查或信息范围说明等独立页面。研究截止日期放在封面或页脚；资料缺口在相关正文或末尾来源清单中简要说明。

目录默认显示一级和二级标题。三级标题只用于确有必要的复杂部分，通常不进入目录。

### 第一章“核心结论”

控制在两至四页，从以下问题中选择与本次任务直接相关的内容；完整客户研究通常覆盖多数问题，专题报告不要求逐项出现：

- 这是一家怎样的客户，目前最值得注意的变化是什么；
- 上级集团数智化与AI规划如何影响目标单位；
- 谁控制需求、技术、预算、采购、实施和验收；
- 内部数字科技/三产公司在链条中处于什么位置；
- 哪些方向与朗坤智慧高/中/低匹配，为什么；
- 最大障碍、反例和待核实事项是什么。

### 主体章节

围绕用户最需要解决的问题选择章节。默认主线为：核心结论→客户业务、资产和经营情况→上级集团、分子公司和重点单位→组织架构、部门职责和领导情况→数智化与AI规划、现有系统和建设空间→内部数字科技公司、投资项目和招标采购→现有供应商、竞争厂商和合作伙伴→朗坤智慧可重点跟进的项目方向→下一步建议联系的单位、部门、人员及待核实事项。具体一级、二级标题参照 [evidence-and-output.md](evidence-and-output.md) 的“面向营销团队的报告结构”，可按本次任务合并、扩展或调整。

采用以下控制原则：

- 用户明确提出的问题和材料优先于默认模板；
- 二三级单位必须解释上级集团的具体要求、集团已统一建设的内容及下属单位可自主建设的范围，但可融入相关章节；
- 只有需要解释演进时才使用时间线或纵向追踪；
- 只有存在可比对象和统一口径时才做横向比较；
- 只有能揭示采购链或合作入口时才单设内部数科公司章节；
- 与本次任务关联弱的模块应压缩，而不是为了“全面”平均分配篇幅；
- 每章必须形成判断，不能把搜索结果按主题重新分类后直接成文。
- 每个一级章节通常设置二至五个能够概括具体内容的二级标题；连续三页以上只有一级标题和正文时，优先增加二级标题；只有一两句话的二级标题应合并，避免目录碎片化。
- 标题直接写明对象和内容，不使用“账户推进、购买中心、机会组合、竞争生态、红队审查”等内部术语或抽象词。

结尾应落到朗坤智慧匹配度、可以采用的合作方式、可能导致项目无法推进的因素和待核实问题，但不输出30/90/180天计划、里程碑和退出条件。

## 三、视觉与版式规范

### 页面与风格

- 使用A4纵向作为默认页面；仅对确有必要的宽表使用A4横向页面。
- 采用克制、专业的能源工业风格，以深蓝、青蓝或蓝绿色为主色，搭配深灰正文和浅灰底色。
- 不使用大面积高饱和渐变、廉价科技光效、无关能源照片或装饰性图标。
- 不使用未经用户提供或授权的企业标识。可使用纯排版封面和抽象线条形成视觉识别。
- 在封面标注客户法定全称、“大客户深度研究报告”、研究截止日期、“朗坤智慧科技股份有限公司”和“内部研究参考/基于公开信息”；用户要求对外版本时再去掉内部研究属性。

### 字体与层级

- 优先选择环境中真实存在且可嵌入的中文字体，如思源黑体、思源宋体、Noto Sans CJK或Noto Serif CJK。
- 正文使用适合长文阅读的宋体类或清晰无衬线字体，通常为10.5—11.5磅；行距约1.35—1.55倍。
- 一级标题和二级标题形成稳定的默认层级；三级标题仅用于区分复杂的业务板块、子公司或项目，不超过四级标题。
- 表格和图注不得小于8.5磅；内容过多时拆表或改为横向页面，不能无限缩小字号。
- 数字、英文、单位和中文标点保持一致，不混用全角与半角格式。

### 页眉页脚与导航

- 页眉显示客户简称和报告主题，避免重复完整长标题。
- 页脚显示研究截止日期、内部研究属性和连续页码。
- 目录必须与最终页码一致；PDF书签可用时同步生成。
- 章节首页保留适度留白，但不人为制造大块空白或独立空白页。
- 图、表分别连续编号，并在正文中有明确引用。

### 表格

- 表头使用主色或浅色底纹，正文采用轻量分隔线，避免全表粗黑边框。
- 同一列保持对齐规则：文本左对齐、数值右对齐、状态居中。
- 长文本单元格使用短句和分层表达，避免把整段正文塞入表格。
- 跨页表格重复表头，避免一行被不合理拆断。
- 超宽表优先拆成“事实表+判断表”，其次才使用横向页。

## 四、图表与可视化

只在视觉表达能显著提升理解时使用图表。根据数据和证据选择：

| 研究问题 | 优先形式 |
|---|---|
| 集团、产权和上下级关系 | 自上而下实体树或分层结构图 |
| 业务板块、资产和地域分布 | 业务资产矩阵；有精确地理数据时使用地图 |
| 收入、利润、装机、产量等变化 | 折线图或分组柱状图 |
| 集团政策如何向下影响目标单位 | 政策传导图 |
| 领导、政策、项目和系统的演进 | 多轨时间线 |
| 部门在立项、技术、采购、使用和验收中的职责 | 项目相关部门及人员表或职责关系图 |
| 内部数科公司、外部厂商和最终用户关系 | 现有供应商、竞争厂商、内部数科公司和最终用户关系图 |
| 子公司或同业差异 | 比较矩阵或小倍图 |
| 朗坤智慧适配方向 | 朗坤智慧可跟进项目方向比较表 |

执行以下规则：

- 每张图表必须表达一个明确问题，并在图后解释“这意味着什么”。
- 在标题或图下注明数据口径、时间范围、单位和来源。
- 不把定性判断伪装成精确数值，不为画图虚构比例或评分。
- 不用搜索结果截图代替图表；从可核验数据重新绘制。
- 不使用低清晰度截图。必须使用截图时裁掉无关界面，并保证文字在100%缩放下可读。
- 不使用无可比尺度的雷达图，不使用大量3D饼图或装饰性仪表盘。
- 配色兼顾灰度打印和色觉差异；不能只依赖红绿区分状态，同时使用文字标签。

## 五、引用与证据呈现

- 对关键事实就近标注来源序号、发布日期或脚注，不把所有证据推到报告末尾。
- 在图表下方写明来源和必要的计算说明。
- 在报告末尾列出完整来源名称、发布主体、发布日期、访问日期和可访问链接。
- 不在PDF中留下内部工具引用标识、搜索结果编号、临时路径或占位符。
- 控制直接引文长度。优先忠实概括，并明确区分事实、推断、销售假设和待核实信息。
- 对存在冲突的来源并列说明，不通过版式隐藏不利证据。

## 六、PDF生成流程

严格按以下顺序执行：

1. 完成实体核验、证据台账和章节提纲。
2. 写完1万—3万字正文并完成事实、逻辑、重复和匹配度审校。
3. 统计正文有效字数，并检查篇幅是否集中在用户最关心、最有证据和最有决策价值的章节。
4. 根据真实数据生成图表、时间线、实体树和比较矩阵。
5. 将正文、表格、图表、脚注和来源编排为统一文档。
6. 生成PDF，并检查文件可正常打开、页数合理、文字可选择和链接可用。
7. 使用文本提取工具检查中文乱码、正文缺失、未替换占位符和实际字数。
8. 使用Poppler等工具将最终PDF全部页面渲染为PNG。
9. 先查看全页缩略图发现空白页、节奏失衡和异常页面，再按原始尺寸检查封面、目录、章节首页、宽表、图表、来源页及所有异常页。
10. 修正问题后重新生成并重新渲染；以最后一次渲染结果作为交付依据。

不要把“生成成功”视为排版通过。文字提取只能验证内容存在，不能替代视觉检查；缩略图只能发现全局问题，不能替代原尺寸检查。

## 七、逐页验收与交付

### 内容验收

- 正文有效字数位于10,000—30,000字；
- 报告结构与用户目的、客户层级和已有材料匹配，没有机械套用纵向、横向或其他固定框架；
- 报告结论能追溯到证据；
- 上级集团、内部数科公司、现有供应商、竞争厂商、合作伙伴和朗坤智慧匹配均已覆盖；
- 封面之后只有报告目录，随后直接进入第一章“核心结论”；
- 目录至少显示一级和二级标题，标题能直接说明具体单位、人员、项目、厂商或风险；
- 没有把“使用说明、研究方法、证据纪律、红队审查、账户推进、购买中心、机会组合、竞争生态”等写成报告章节或图表标题；
- 没有百分制商机评分、30/90/180天计划、里程碑和退出条件；
- 没有将深圳市朗坤科技股份有限公司信息误归入朗坤智慧。

### 版式验收

- 封面、目录、章节层级、页眉页脚和页码完整；
- 中文字体无缺字、方框、乱码或替换异常；
- 没有文字截断、重叠、超出页边距或孤立标题；
- 没有异常空白页、重复页面或内容顺序错误；
- 表格没有超宽、跨页断裂、表头丢失或小字难读；
- 图表清晰，图例、单位、来源和编号完整；
- 目录页码、正文交叉引用和来源编号一致；
- PDF内不包含临时路径、工具标记、测试文字或未替换占位符。

### 文件命名与交付

使用稳定、清晰的中文文件名：

`客户法定全称_大客户深度研究报告_YYYYMMDD.pdf`

交付时用简短文字说明：

- 研究截止日期；
- 正文约多少字；
- 最重要的三至五条判断；
- PDF文件链接；
- 公开信息仍无法确认的关键事项。
